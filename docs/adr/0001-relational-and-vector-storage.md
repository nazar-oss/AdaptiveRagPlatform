# ADR-0001. Поєднання PostgreSQL (EF Core) та Qdrant для зберігання даних

## Статус
Прийнято

## Контекст
Платформа потребує надійного транзакційного зберігання структурованих даних (користувачі, навчальні матеріали, тести, результати спроб, журнал викликів LLM) та швидкого семантичного пошуку за векторними поданнями (ембедінгами) текстових фрагментів для роботи RAG-конвеєра.

## Рішення
Використовувати гібридне сховище: PostgreSQL у зв'язці з Entity Framework Core (підхід code-first) для всіх реляційних сутностей та Qdrant як спеціалізовану векторну базу даних для індексації й пошуку фрагментів навчальних матеріалів.

## Альтернативи
* **Використання лише PostgreSQL із розширенням pgvector:** спрощує інфраструктуру (один контейнер), але при масштабуванні великих обсягів навчальних курсів і складному фільтруванні метаданих векторний пошук у Qdrant працює швидше та має кращі вбудовані інструменти індексації HNSW.
* **Документна БД (MongoDB):** не забезпечує суворої реляційної цілісності між тестами, питаннями, спробами студентів та журналом витрат токенів LLM.

## Наслідки
* **Позитивні (+):** висока швидкість і точність семантичного пошуку в Qdrant; сувора цілісність даних, транзакційність і зручні міграції схеми через EF Core у PostgreSQL.
* **Негативні (−):** необхідність підтримувати два окремі сервіси баз даних у Docker Compose та синхронізувати видалення/оновлення матеріалів між PostgreSQL і Qdrant.
