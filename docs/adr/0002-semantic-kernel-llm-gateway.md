# ADR-0002. Ізоляція звернень до LLM через Semantic Kernel та власний інтерфейс

## Статус
Прийнято

## Контекст
Генерація адаптивних тестових завдань, ембедінгів та перевірка відкритих відповідей студентів залежать від зовнішніх LLM-провайдерів. Прямі виклики API провайдера з контролерів створюють жорстку залежність, ускладнюють тестування без витрат токенів та не дають єдиної точки обліку затримок і вартості запитів.

## Рішення
Винести всю логіку формування промптів, оркестрації RAG та викликів моделей в окремий модуль `AdaptiveRag.Ai` на базі Microsoft Semantic Kernel. Доступ до модуля з `AdaptiveRag.Api` здійснюється виключно через власну абстракцію (`IRagAssessmentService` / `ILlmGateway`), а ключі доступу зберігаються лише у змінних середовища на сервері.

## Альтернативи
* **Прямі HTTP-запити до REST API провайдера з сервісів API-сервера:** швидше на старті, але заміна моделі чи провайдера потребуватиме переписування бізнес-логіки, а також доведеться вручну реалізовувати повтори (retries) та парсинг відповідей.
* **Виклик LLM безпосередньо з клієнтського застосунку (Blazor/React):** категорично відкинуто через ризик витоку API-ключів та неможливість контролювати системні промпти й облік токенів.

## Наслідки
* **Позитивні (+):** легка заміна LLM-провайдера або моделі без зміни бізнес-логіки; можливість підставити mock-реалізацію для локального тестування; централізоване логування кожного виклику в таблицю `LlmCallLog`.
* **Негативні (−):** додатковий рівень абстракції та початкові витрати часу на проєктування DTO-моделей запитів і відповідей.
